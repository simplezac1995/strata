# 结构约定（三端）

> 目的：让「问题在哪、改哪里、加功能」三个问题都能在**不搜索**的情况下回答。
> 规则是**规范性**的：新代码必须遵守；存量代码在被改动时顺带迁移，不做一次性大重命名（会制造冲突）。

---

## 一、后端（strata）

### 1.1 模块边界

| 层 | 模块 | 规则 |
| :--- | :--- | :--- |
| 入口 | `strata-app` | 只装配：`StrataApplication`、`application*.yml`、跨模块 Web 测试 |
| 业务 | `strata-casino` / `strata-system` / `strata-ai` / `strata-pro` / `strata-enterprise` / `strata-plugin` | 按**产品域**拆；域内再按**功能**拆子模块 |
| 公共 | `strata-common` | 无业务语义的技术能力；**不允许**反向依赖业务模块 |
| 基础设施 | `strata-migrations` / `strata-generator` / `strata-coverage` / `strata-starter` | 迁移、代码生成、覆盖率、外部接入 |

依赖方向只能 **下游 → 公共**，公共模块不得 import 业务模块。模块内部的功能子模块之间**禁止互相 import 实现类**，只能依赖对方的 `api` 包。

### 1.2 功能子模块内部包结构（标准四层）

```
dev.strata.<域>.<功能>.
  ├── api/            ← 对外契约：DTO / Request / View / 枚举 / 跨模块接口
  ├── domain/         ← 领域模型与仓储：entity / repository 接口 / 领域事件
  ├── app/            ← 用例编排：*AppService（一个用例一个方法，事务边界在这里）
  ├── web/            ← HTTP 入口：*Controller（不可叫 web/controller 之外的第三种名字）
  └── config/         ← 该功能的 Spring 配置
```

**强制约定：**

1. **一个包层级只用一个划分维度。** 现有 `biz/` 下把「业务子域（bonus、affiliate）」和「技术层（service、repository、web）」混放，是最大的可维护性负债。新代码**不得**再建 `biz/<子域>/`，业务子域用**类名前缀**表达（`BonusAdminController`、`BonusRepository`）。
2. **HTTP 入口只放 `web/`**，类名 `*Controller`。存量 `biz/controller` 逐步迁到 `web/`（改包时同步移动文件，IDE 重构）。
3. **`api/` 是可被其他模块 import 的唯一包**；其他模块只允许依赖 `api` 下的 DTO/接口，不得依赖 `app`/`web`/`domain` 实现。
4. **测试与被测类同包**（`src/test/java` 下镜像包名），测试类名以 `Test` 结尾；跨模块/端到端测试放 `strata-app`。

### 1.3 命名

| 类型 | 规则 | 反例 |
| :--- | :--- | :--- |
| HTTP 入口 | `XxxController` | `XxxEndpoint`、`XxxResource` |
| 用例编排 | `XxxAppService`（跨聚合、带事务） | 把编排塞进 `XxxService` |
| 领域服务 | `XxxService`（单一聚合内、无跨服务编排） | — |
| 持久化 | `XxxRepository`（Spring Data 接口） / `XxxDao` 仅限 JdbcTemplate | `XxxManager` |
| 传输对象 | `XxxDto`（出参）、`XxxRequest`（入参） | `XxxDTO`、`XxxVO`、`XxxBO` |
| 映射 | `XxxMapper`（MapStruct） | `XxxConverter`（若手写转换才用） |
| 配置 | `XxxConfiguration`（`@Configuration`） / `XxxProperties`（`@ConfigurationProperties`） | `XxxConfig`（存量 14 个，改到时统一） |
| 事件 | `XxxEvent` / `XxxListener` | `XxxHandler` 用于外部回调时保留 |
| 工具 | `XxxUtil`（无状态静态）、`XxxSupport`（包内辅助） | `XxxHelper`、`XxxUtils` |

### 1.4 单文件上限

- **目标 400 行，硬上限 500 行**。超过必须拆（按职责拆，不是按行数切）。
- 当前超标（P0 待拆）：`GeneratorService` 860、`WithdrawalService` 685、`BscWalletOpsService`/`TronChainClient`/`ChainMonitorService` 26-27KB。
- 一个类只允许一个 `@Transactional` 边界语义；跨聚合编排放 `AppService`。

### 1.5 常量与魔法值

- 业务常量集中在功能模块的 `*Constants` 或 `*Properties`；**禁止**在 Controller/Service 内联字符串 key。
- 定时任务、缓存名、Redis key 前缀必须定义为常量并在 `config/` 中注册。

## 二、后台管理端（strata-ui）

### 2.1 目录

```
src/
  app/          ← 启动、路由、Provider（不放页面）
  shell/        ← 应用壳：Sidebar / navigation / layout（从 components 拆出）
  pages/<域>/   ← 页面：每页 <= 300 行；复杂页拆 `<页>/sections/*.tsx`
  features/<域>/← 可复用业务逻辑：hooks / api / 类型 / 计算
  shared/       ← ui 组件、api-client、i18n、utils、hooks（无业务语义）
```

- `pages/` 只放**路由可达**的页面组件；不允许把业务组件塞进 `components/`。
- `components/shell/*` 迁往 `shell/`（导航、布局属于壳，不属于通用组件）。
- 页面文件名与组件名一致（PascalCase）；hooks 以 `use` 开头 camelCase；其余模块 camelCase。

### 2.2 i18n（本目录整改后）

```
shared/i18n/
  dict/en/<prefix>.ts   ← 一个 key 前缀一个文件（ai / casino / system / nav / common ...）
  dict/zh/<prefix>.ts
  en.ts                 ← 只做聚合 export，不放开编辑
  zh.ts
  index.tsx             ← 语言切换、校验、类型
```

- **新增文案**：先找前缀文件，找不到再新建前缀文件并在 `index` 聚合。
- 键保持 `prefix.xxx.yyy` 扁平结构（现有约定），不改成嵌套对象。
- `npm run i18n:verify` 必须通过（en/zh 键集合一致）。

### 2.3 单文件上限

- **目标 300 行，硬上限 500 行**。当前 18 个文件超标，最严重 `pages/ai/more/Bidding.tsx` 1,133 行。
- 拆分原则：数据/常量 → `<页>/content.ts`；可复用小组件 → `primitives`；每个步骤/面板 → 独立文件。

## 五、超大文件（>500 行）的拆分方式

硬上限靠工具落地，不要手拆。`strata-ui/scripts/` 下有两个一次性工具，可以组合使用：

| 脚本 | 用途 |
| :--- | :--- |
| `auto-split.mjs <file...>` | 把次要声明搬进同目录分片文件：重建 import、修正相对路径、生成跨文件 import、把搬走的导出从源码 re-export；组件只有一个末尾 `return` 时，把 state/handlers 抽成 `use<Name>` hook。泛型组件跳过（类型参数无法安全搬移）。可用 `MAX_LINES=340` 降低触发阈值。 |
| `extract-view.mjs <file...>` | 把 JSX 抽进 `<Name>View`（对话框抽进 `<Name>ViewDialogs`），视图接收 hook 返回值 `view` 并在组件内解构还原原名——JSX 逐字复制，不触碰字符串/属性名；组件 props 以 `{...{ a, b }}` 透传。 |

流程：`node scripts/auto-split.mjs <file>` → `npx prettier --write <file 与目录>` → `npx tsc -b` → 若仍超 500 行再 `node scripts/extract-view.mjs <file>` → 重复直至达标 → `npm run check`。

拆分后的入口文件保持**原路径可导入**（barrel / re-export），调用方零改动；这也是判断拆分是否正确的标准——`tsc` 通过 + 测试通过 + 门禁全绿。

## 六、上限的自动检查

`scripts/verify-file-size.mjs` 扫描 `strata/**/*.java`、`strata-ui/src/**/*.{ts,tsx}`、`frontend/src/**/*.{ts,tsx}`，任何文件超过 500 行即失败；`i18n` 目录属于字典数据，明确豁免。它已接入 `scripts/verify-all.*` 的「仓库一致性」步骤和 CI 的 consistency job，所以上限不靠记忆，靠门禁。
