# 03 · 架构设计

> 本文说明 Strata Admin 的运行形态、模块分层、依赖约束、双 HTTP 面、请求横切链路与扩展机制。
> 命名与代码组织的硬规见 04-工程规范，取舍背景见 adr/。

## 1. 形态：模块化单体，不做微服务

系统是**单进程、单可部署单元**（`strata-app`），但在源码层用 Maven 多模块 + 领域包结构强制边界。
选择模块化单体而非微服务的理由：团队与规模不需要分布式代价；模块边界在**编译期与测试期**就被强制，
未来确有必要时可沿模块缝拆分，而不是现在就引入网络边界、分布式事务与运维复杂度。

- 进程内横切（认证、限流、幂等、审计、事务）以 Servlet Filter / AOP / Spring Bean 实现，无远程调用。
- 部署形态固定为 Docker Compose；不提供也不维护 K8s / Helm / GitOps 的一等支持（历史目录 CI 不部署）。
- 唯一的"分布式"依赖是数据库与 Redis（登录锁、令牌黑名单、分布式锁），均为可选/可替换。

## 2. 模块分层：`-api` 契约与 `-biz` 实现

每个领域拆两类 Maven 模块：

| 模块 | 内容 | 可被谁依赖 |
| :--- | :--- | :--- |
| `*-api` | 对外实体/DTO、服务端口接口、领域异常、枚举 | 其他域的 `*-biz` |
| `*-biz` | Controller、AppService、Repository 实现、Mapper、业务逻辑 | 仅装配层 `strata-app` |

单个域内固定四层（以 system/rbac 为例）：

| 层 | 包 | 职责 |
| :--- | :--- | :--- |
| Controller | `dev.strata.<域>.<子域>.biz.web` | 参数绑定、`@PreAuthorize`、调用 AppService、返回 `Result` |
| AppService / Service | `...biz.appservice`（或 `...biz.service`） | 用例编排、事务边界；横切 `*Service` 走 `service.support` 白名单（ADR-0015） |
| Repository | `...biz.repository` | Spring Data JPA 接口与数据访问实现 |
| Domain / DTO | `...api.entity`、`...api.dto` | 实体与出入参 |

约束：

- Controller 不得直接注入 Repository；DTO ↔ 实体一律用 MapStruct（Mapper 统一在 `...biz.mapper`）。
- 同一类型只定义一次：如 `Ai*` 契约只在 `strata-ai-api`，禁止在 `*-biz` 重复。
- 目录名与包名一一对应。HTTP 入口统一放在 `...biz.web`（2026-11 已把存量 `...biz.controller` 全部迁入 `web`，并由 ArchUnit `controllersLiveInWebPackages` 锁定；`docs/17` 是结构约定的权威）。
- `*-api` 中的 JPA 实体是现存模块间契约的一部分；新跨域调用优先使用 DTO/服务端口，不把对方实体当作可随意读写的业务 API。

## 3. 依赖约束（编译期 + 测试期双保险）

合法依赖方向：

```
strata-app  →  各域 *-biz  →  本域 *-api  →  strata-common-*
                   │
                   └──────────────→ 其他域 *-api（只能依赖契约，不能依赖对方 biz）
```

- **跨域只允许依赖对方 `*-api`；禁止 `biz → 其他域 biz`**；插件不依赖业务实现。
- 强制手段：
  - Spring Modulith `ModulithVerificationTest`（验证模块依赖与事件边界）；
  - ArchUnit `ArchitectureRulesTest`（分层、模块仅依赖 api、域模块不得耦合 system biz 实现等）；
  - 二者挂在 `mvn verify`，违反即构建失败——这是设计意图，不是误报。

## 4. 双 HTTP 面（ADR-0026）

系统有意区分两套边界，各自有独立安全过滤链：

| 面 | URL 前缀 | 受众 | 认证 / 授权 |
| :--- | :--- | :--- | :--- |
| 员工管理端（staff） | `/api/v1/<域>/...` | 后台用户 | JWT + 菜单权限串（`module:entity:action`） |
| 玩家端（player） | `/v1/...` | H5 玩家、聚合商回调 | 玩家会话不透明令牌；回调走签名/AES 信封 |

- staff 例：`/api/v1/system/users`、`/api/v1/ai/models`、`/api/v1/demo/products`。
- player 例：`/v1/auth/session`、`/v1/wallet/**`、`/v1/games`、`/v1/game/callback`。
- 免鉴权路径不由核心安全配置硬编码业务 URL，而由各模块实现 `PermitPathContributor` 自声明、装配层汇总（ADR-0021）。

## 5. 一次 HTTP 请求的横切链路

```
HTTP 请求
  → TraceIdFilter（MDC 写入 traceId，响应头 X-Trace-Id）
  → RateLimitFilter（路径级令牌桶，安全链之前；聚合商回调路径不节流）
  → SecurityFilterChain（staff 链 / player 链 二选一；CORS、安全头、JWT/会话认证、@PreAuthorize）
  → 幂等过滤器（写请求按 Idempotency-Key 去重 / 重放首次响应，ADR-0027/0034）
  → XSS / 敏感词清洗（可按 URL 排除）
  → DispatcherServlet → Controller（@PreAuthorize 方法级）
  → AppService（@Transactional 编排）→ Repository（JPA）
  → 成功：Result<T>（ResultTraceAdvice 自动回填 traceId）
  → 异常：GlobalExceptionHandler / SecurityExceptionHandler / PlayerApiExceptionHandler
          统一转 RFC 7807 Problem Details
  → 审计切面 @Audit（受控操作留痕，异步落库/文件）
```

- 成功体：`Result<T>`；错误体：`application/problem+json`，字段 `type/title/status/detail/code/timestamp/traceId`。
- 业务错误先在 `ErrorCode` 枚举登记，再抛业务异常；禁止 Controller 手搓 JSON、禁止 `PATCH`。
- 安全机制细节与**已知安全债**见 08-安全设计。

## 6. 扩展机制

### 6.1 插件 SPI（ADR-0006）

能力以 SPI 接口 + 内置插件提供，默认关闭、按需开启，配置挂 `strata.plugin.*`：

| 插件 | 能力 | 开关（默认） |
| :--- | :--- | :--- |
| storage-local / S3 | 对象存储 | `strata.oss.type` |
| stripe | Stripe Checkout + Webhook（demo 支付） | `strata.plugin.stripe.enabled=false` |
| llm-openai | OpenAI 兼容 LLM 推理（AI Chat） | `strata.plugin.llm.openai-compatible.enabled` |
| excel | Excel 导入导出 | 按需 |
| encrypt-aes | 敏感字段 AES 载荷加密 | `strata.plugin.encrypt.aes.enabled=false` |
| workflow-flowable | Flowable 工作流执行引擎 | `STRATA_FLOWABLE_ENABLED`，默认关 |

新增能力遵循"插件黄金路径"：一个自包含 Maven 模块实现 SPI，不反向依赖业务实现（ADR-0020）。

### 6.2 工作流与多租户的 Open Core 分层

- 工作流：Community 为队列 **stub**（可配置、可跑通元数据）；Enterprise 为 Flowable 插件 opt-in（ADR-0018）。
- 多租户：Community 为**目录级**租户；**行级隔离**是显式开关（`strata.tenant.row-level-enabled`），
  开启后由 `TenantScopeSupport` 过滤（ADR-0012 / 0023）。

## 7. 关键领域设计

- **资金（casino-wallet）**：金额用最小单位整数；资产注册表 + 复式账本，余额只有账本一个写入者；
  支付意图带确定性 `entry_no`；账本归档"移动而非删除"，不为分区改资金表主键（ADR-0028 / 0031）。
- **玩家会话（casino-player）**：不透明令牌只存哈希；刷新轮换、复用已轮换令牌则整链吊销；登录失败锁定
  （ADR-0029）。
- **幂等**：管理端写操作稳定携带 `Idempotency-Key`，401 刷新重试复用同键；`/v1` 聚合回调以业务流水号
  幂等；玩家充值意图与提现端点均强制 `Idempotency-Key`，同 key 异 payload 返回 409（ADR-0034）。
- **前端托管**：SPA 在镜像构建期产出并注入 jar 的 `classpath:/static`，单体同源托管；静态资源匿名、
  API 必鉴权，BrowserRouter history fallback（ADR-0035）。

## 8. 架构边界（明确不做）

- 不拆微服务、不引入服务注册 / 网关 / Feign / Dubbo。
- 不做 OSGi 式运行时热插拔；插件是 Spring 条件装配，随进程启动。
- 核心不引入 MyBatis-Plus 或第二套 ORM；前端不引入第二套 UI 框架（唯一 MUI 9 + `components/ui`）。
- 不为"表面整齐"批量重命名已对外术语，不保留旧 API 转发文件。
